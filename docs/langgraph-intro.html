LangGraph, from messages to agents

LangChain gives you the parts (models, messages, tools). LangGraph gives you the wiring: a stateful graph runtime with loops, branching, persistence and human pauses. This page covers the core ideas, each tied to a runnable demo in demos/.

01Where each library fits

Think of three layers. You can work at any of them, and each one is built on the layer below.

Rule of thumb: start with create_agent if the standard "LLM ↔ tools" loop is enough. Drop down to StateGraph when you need custom state, deterministic steps, branching, parallel fan-out or approval gates.

02Three primitives: state, nodes, edges

State

The shared memory

A TypedDict (or Pydantic model). Every node reads it; nodes return partial updates, never the whole thing.

Node

A plain function

def node(state) -> dict. Call an LLM, run a tool, hit an API or just do maths. It's all Python.

Edge

What runs next

Fixed (add_edge) or conditional (add_conditional_edges, a function that returns the next node's name).

class State(TypedDict):
    number: int

def double(state: State) -> dict:
    return {"number": state["number"] * 2}      # partial update

builder = StateGraph(State)                          # 1. declare the state schema
builder.add_node("double", double)                   # 2. register nodes
builder.add_edge(START, "double")                     # 3. connect them
builder.add_edge("double", END)
graph = builder.compile()                            # 4. compile → a Runnable
graph.invoke({"number": 21})                          # {'number': 42}

03Reducers: how updates merge into state

When a node returns {"key": value}, LangGraph merges it into the state using that key's reducer. No reducer means overwrite. Annotated[list, operator.add] means append. MessagesState uses add_messages, which appends but also updates a message if one with the same ID already exists.

04The agent loop, step by step

The classic tool-calling agent (ReAct) is just a two-node graph with a cycle. Step through it to see how the messages list grows. This is demos/05_tool_agent.py.

state["messages"]
    builder = StateGraph(MessagesState)

builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)   # → "tools" or END
builder.add_edge("tools", "agent")                       # the loop
graph = builder.compile(checkpointer=InMemorySaver())

    05How a graph actually runs: super-steps

    LangGraph follows Google's Pregel model. Execution is a sequence of super-steps. In each one, every node that was triggered runs (in parallel if there are several). Their updates are merged through the reducers, and a checkpoint is saved. Then the edges decide which nodes run in the next step.

    That is why reducers matter for parallel branches, and why persistence, time travel and interrupts come for free once you add a checkpointer.

    06Pattern gallery

    A workflow follows paths you define in code. An agent lets the LLM pick its next action. Most real systems mix the two.

    The LLM only classifies, and a conditional edge picks the branch. This is predictable, cheap and easy to test. demos/04_llm_router.py

    builder.add_conditional_edges("classify", lambda s: s["category"],
    {"billing": "billing_agent", "tech": "tech_agent", "other": "general_agent"})

    You only find out how many branches you need at runtime. The router returns a list of Send objects, each with its own input. Their results are merged by a reducer. demos/09_map_reduce_send.py

    def fan_out(state):
    return [Send("write_section", {"section": s}) for s in state["sections"]]
builder.add_conditional_edges("plan", fan_out, ["write_section"])

    interrupt(payload) stops the run and saves state. You can resume it later, even from another process, with Command(resume=value). That value becomes the return value of interrupt(). This needs a checkpointer. demos/07_human_in_the_loop.py

    On resume, the interrupted node runs again from its beginning. Keep any side effects that come before interrupt() idempotent.

    Retrieval becomes just another tool. The agent decides whether to search, and what to search for. demos/08_rag_agent.py

    Each sub-agent is a graph of its own. Subgraphs can be added as nodes (demos/12_subgraphs_and_streaming.py), or sub-agents can be wrapped as tools. Agents can hand off control by returning Command(goto="agent_name", update={...}). demos/11_multi_agent_supervisor.py: the supervisor writes a focused task for each worker, so each sub-agent sees only what it needs.

    07Persistence, threads and time travel

    Pass a checkpointer to compile(), then pass {"configurable": {"thread_id": "..."}} on every call. Each thread is its own conversation with its own checkpoint history.

    CheckpointerPackageUse for
    InMemorySaverlanggraphDemos and tests. Lost when the process exits.
    SqliteSaverlanggraph-checkpoint-sqliteLocal apps that need state to survive restarts (demo 10).
    PostgresSaverlanggraph-checkpoint-postgresProduction.

    Checkpointers hold per-thread short-term memory. For long-term memory shared across threads (user preferences, facts), use a Store: compile(store=InMemoryStore()).

    09Learning path (the demos)

    Run them with uv run demos/NN_name.py. Each file starts with a docstring that lists the concepts it covers.

    1. 00_check_setup
      Is Ollama reachable, are the models pulled, does one LLM call work?
    2. 01_chat_model_basics
      Messages, invoke / stream / batch, prompt | model | parser.
    3. 02_tools_and_structured_output
      Tool calling by hand, ToolMessage, Pydantic structured output.
    4. 03_state_graph_basics
      State, reducers, nodes, edges and loops. No LLM, so it runs instantly.
    5. 04_llm_router
      Workflow pattern: LLM classification followed by a conditional edge.
    6. 05_tool_agent
      The ReAct loop as an explicit graph, with memory through thread_id.
    7. 06_create_agent
      The same loop in one call, plus response_format.
    8. 07_human_in_the_loop
      interrupt(), inspecting the pause, Command(resume=...).
    9. 08_rag_agent
      Embeddings, vector store, retrieval as a tool.
    10. 09_map_reduce_send
      Dynamic parallel fan-out with Send and a reducer.
    11. 10_persistence_time_travel
      SQLite checkpoints, state history, replay and fork.
    12. 11_multi_agent_supervisor
      Supervisor plus specialist sub-agents, routed with Command(goto=...).
    13. 12_subgraphs_and_streaming
      A compiled graph as a node; updates / custom / messages stream modes and subgraphs=True.

    To check that everything still runs after a change: uv run pytest -m "not llm" takes seconds and needs no model. uv run pytest runs every demo end to end.
